# PIN-0031 — Computed Action Center

**Type:** Feature · **Phase:** 9 · **Status:** Review

Spec: `.codex/specs/daily-brief.md`, Q1–Q6.

## Scope
1. Cards come from six rules over the shop's data, each with a stable key (`stock:ML-CV-018`).
2. Every card states why it appeared, what happens if it is skipped, and one action that goes
   where the work is. Amounts only where they are facts.
3. The four seeded actions, the "92%" confidence and the headline impact total are removed.
4. "ซ่อนถึงพรุ่งนี้" stored in `action_snoozes`; the resolve route goes.
5. Days left computed from 7-day sales, on Stock and in the brief; seed `on_hand` scaled.
6. Pack window is `shops.pack_window_hours`, default 24.

## Acceptance criteria
- [x] Every card on screen traces to rows; none is typed into a fixture.
- [x] Ad and cost cards never reach staff — in the payload, not just the view.
- [x] A snoozed card stays hidden until the next Bangkok day, for that shop only.
- [x] A card disappears by itself when its condition clears.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.

## Review notes

### What changed
- `db/brief.ts` (new): six rules — stock running out (days left from 7-day sales), orders past
  the shop's pack window, orders under review, unread chats, and owner-only ad-spend-ratio and
  missing-cost cards. Every card carries why / if skipped / what to do / data used, and a
  factual amount or none.
- Removed: the four fixture actions (`app/fixtures/actions.ts`), the drawer's literal "92%",
  the headline "ผลกระทบรวม" sum, the resolve route and `resolveAction`, `listActions`,
  `openActionImpactTotal`, `formatUpdatedAt`.
- `POST /api/actions/snooze` + `action_snoozes`: hide a card until the next Bangkok midnight.
  Unknown/malformed keys 400; staff snoozing an owner-only card 403.
- Migration **0008** (additive): `action_snoozes`, `shops.pack_window_hours` default 24.
- Stock view's "ขายได้อีก" and status now use the same computed days left.
- Seed: stock sized to sales via `stockForDays()` (shared with the production script);
  `actions` stays empty.
- CSS: at 721–760 px a card's amount fell into the 20 px arrow column and was clipped (it
  would have clipped the old "เสี่ยงเสีย ฿3,240" too). Placed under the text, as ≤720 px does.

### Verification
- 63/63 tests; tsc and lint clean. New tests compute expectations in SQL independently of the
  rules, and each was falsified — 8 mutations (urgency threshold, owner cards to staff, snooze
  ignored, staff snoozing owner cards, pack window hard-coded, ads rule never firing, velocity
  window, snooze lasting 24 h instead of to midnight), 8 caught.
- Live, owner: 6 cards (3 urgent); snooze persisted with `until` = next 00:00 Bangkok; drawer
  shows data used, no confidence figure. No overflow or clipped text at 1440 / 1024 / 760 / 390.
- **Rehearsed on an export of production:** migration 0008 + the stock update applied; every
  other table identical; the brief served from that copy shows the same six cards, dated
  "ข้อมูลถึง 12 ก.ย. 15:09 น.".

### Not done here

  sizes stock; dry run passes against production). Deploying first would fail — the brief reads
  `action_snoozes` and `pack_window_hours`.
- The pack-late and ad-spend rules have no card in the demo: nothing is late and spend is
  steady. Both are proven by tests that create the condition.
- The lamp shows as out of stock while the generated history keeps selling it ~14/day — a
  demo-data inconsistency from PIN-0027's generator, not a rule bug.
- No UI to change the pack window yet; it is a column with a default.
