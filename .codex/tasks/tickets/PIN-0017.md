## Review notes

Every defect below was found by measuring the running page, not by reading the diff. Three
of the four looked correct in the served HTML and in a low-resolution screenshot.

**1. `.brand` was squashed and painted over the nav label.** `.brand` is a flex item in the
sidebar's column, and a `<button>`'s automatic minimum size does not hold it at content
height. Once `.brand-sub` ("Commerce Center") made the brand 53px tall, the sidebar's
content exceeded the viewport, `.brand` shrank to 36px, and its overflow landed on top of
"เมนูหลัก". Measured `clientHeight: 36` against `scrollHeight: 53`. Fixed with
`flex: 0 0 auto`; `.sidebar` already has `overflow-y: auto` to absorb the difference.

**2. The login mascot: `bust` under the first delivery, `full` under the second.** The brief
sets 300px as the floor for the notification chip to read. The first delivery's `full` crop
put the chip too close to the figure to survive at the card's size, so that version shipped
`bust` at 168px with no chip. The redrawn `full` moves the chip clear of the face, and the
card's 304px of content is just over the floor, so it now ships `full` at 300px — which is
also what the second handoff recommends for login. Below a 400px viewport the card narrows
to 286px and `.login-mascot`'s `max-width` scales the artwork down with its ratio intact.

**3. `PintoBrand` distorted the lockup.** Passing `height={30}` emitted the intrinsic
`width="199"` alongside it, rendering the 199×68 artwork as 199×30. The `fit()` helper now
derives the missing dimension from the artwork's own ratio.

The second delivery turned this from a fixed bug into a standing risk: the lockup's ratio
changed from 199:68 to 270:78, so a stale table in TypeScript would have distorted it again.
Every call site now passes **one** dimension and lets `fit()` derive the other, so the ratio
has a single source, and a test compares what the app emits against each file's `viewBox`.
The served markup reads `width="104" height="30"`.

**4. The collapsed sidebar showed a 14px-tall smear.** Below 980px the sidebar is 82px wide.
The lockup scaled down to 41×14 — the wordmark unreadable — and "Commerce Center" wrapped to
two lines. The old text lockup had a `.brand-copy` element that this breakpoint hid; removing
it removed the mechanism. Both marks now ship and CSS picks one: the lockup above 980px, the
head at 34px below it.

Two CSS traps inside fix 4, both now covered by tests:
- `.brand img { display: block }` is specificity (0,1,1) and outranks a bare `.brand-lockup`
  (0,1,0), so the first attempt showed both marks at once. The toggles are scoped to
  `.brand .brand-lockup` / `.brand .brand-mark-only`.
- Media queries add no specificity, so the base `display: none` must appear **before** the
  ≤980px rule that reveals the mark. Placed after, it won everywhere and blanked the
  collapsed sidebar's brand entirely.

### Tests
Two new tests, nine guards, each falsified individually by breaking the thing it protects.

`the sidebar brand survives both CSS traps it fell into` — removing `flex: 0 0 auto`,
reversing the toggle's source order, unscoping either toggle, re-adding `.brand-copy`.

`every brand image is emitted at the artwork's own aspect ratio` — reads each SVG's `viewBox`
and compares it against the width and height the app actually emits. Falsified by restoring
the first delivery's lockup ratio, by drifting the mascot and mark ratios, and by dropping
one dimension from the emitted tag. The first of those is the real bug reproduced: it is
exactly what a third delivery would do if the ratio table were not updated.
