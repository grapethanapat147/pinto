# PIN-0026 — Order lines and unit cost

**Type:** Feature · **Phase:** 8 · **Status:** Done

Spec: `.codex/specs/cost-and-profit.md`, Q1 and Q2. The foundation the other two tickets
stand on.

## Scope
1. `order_lines` — order, product, quantity, unit price, **unit cost snapshot**, all integer
   satang.
2. `products.unit_cost_satang`, nullable — null means "not costed yet", which is different
   from zero and must stay different.
3. Seed lines for every existing order, **summing exactly to each order's `total_satang`**.
   Seed a unit cost for most products but deliberately not all, so partial coverage is real
   data rather than a hypothetical.

## Acceptance criteria
- [x] For every order, the sum of its lines equals its `total_satang` — tested.
- [x] Every line's cost snapshot equals its product's unit cost at seed time.
- [x] At least one product is uncosted, so coverage below 100% exists in the demo.
- [x] Migration is additive only; nothing is dropped.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` (51) pass.

## Review notes

### The lines were solved for, not invented
The fixtures have no prices at all, and inventing lines beside the existing order totals
would have produced two stories about the same order. So prices were **searched** within
believable bands for these home goods until every order's lines summed exactly to its
existing total:

| product | price | cost |
| --- | ---: | ---: |
| แจกันเซรามิกสีครีม | ฿450 | ฿170 |
| โคมไฟ Cloud | ฿1,100 | ฿430 |
| ชุดแก้ว Amber 4 ใบ | ฿640 | ฿250 |
| ผ้าปูโต๊ะ Linen Sand | ฿440 | **uncosted** |
| ถาดไม้โค้ง Natural | ฿340 | ฿120 |

All six orders compose exactly, using all five products across 14 lines. The linen tablecloth
is left uncosted on purpose and appears in four of the six orders, so partial coverage in the
demo is real data rather than a hypothetical.

### Two guards, at two layers
1. **The seed refuses to run** when an order's lines do not sum to its total, naming the order
   and both figures: `Order SP-48218: lines sum to 128000 satang but the order total is 64000`.
2. **A test checks the seeded database itself**, so a seed with that guard removed still gets
   caught.

### Null is not zero
`unit_cost_satang` is nullable and a test fails on any product costed at `0`. Zero would mean
"free" and would silently inflate profit; null means "not costed yet" and keeps that revenue
out of coverage. That distinction is what PIN-0027's coverage display depends on.

### A trap avoided
`money()` was declared with `const` at line 268 of the seed and the new inserts call it at
module load, well before that line. A `const` read before its declaration throws, so the
declaration moved up beside the other conversions with a comment saying why.

### Local data preserved
The local reset is destructive, so the database was backed up first and the LINE row restored
afterwards.

### Tests
Two tests, four guards, each falsified individually: lines that do not sum (with the seed's
own guard disabled so bad data reaches the database), a cost snapshot that disagrees with its
product, a fully costed catalogue, and zero standing in for null.

### Production is untouched
Migration 0006 has **not** been applied to the deployed database. That waits until PIN-0027
gives the new columns a reader, and needs its own decision: the production seed is
destructive and would delete เกรพ's LINE account, so the production order lines should go in
by an additive backfill rather than a reseed.
