# PIN-0019 — The dashboard scrolls sideways on a phone

**Type:** Bug · **Phase:** 5 · **Status:** Review

Found while verifying PIN-0017 at the four agreed breakpoints. **Pre-existing, not caused by
that ticket** — `git show db000dd~1:app/globals.css` has the same ordering.

## The defect
At a 390px viewport the dashboard's document is **729px wide**, so the whole page scrolls
horizontally. 126 elements extend past the right edge. The layout is rendering its desktop
two-column form inside a phone-width viewport.

Measured in the running app:

| | value |
| --- | --- |
| viewport | 390px |
| `document.scrollWidth` | 729px |
| `.overview-grid` computed columns | `473.32px 227.672px` |
| `.overview-grid` width | 716px |

The mobile rules themselves are fine: `matchMedia('(max-width: 760px)')` matches,
`.app-shell` is correctly `display: block`, and the sidebar is correctly a fixed bottom bar.

## Cause
`app/globals.css` is a stack of appended override layers. The ≤760px rule collapsing the
grid sits at line 351; an **unconditional** `.overview-grid` rule sits at line 400. Media
queries add no specificity, so the later unconditional rule wins at every width and the
mobile rule never takes effect.

```
351   @media (max-width: 760px) { … .overview-grid { grid-template-columns: 1fr; } … }
400   .overview-grid { grid-template-columns: minmax(0, 1.58fr) minmax(226px, .76fr); … }
```

This is the same trap PIN-0017 hit with the brand mark toggle, so it is likely not the only
instance. **Audit every unconditional rule that appears after a media query in this file**
rather than fixing `.overview-grid` alone.

## Acceptance criteria
- [x] `document.scrollWidth === innerWidth` on every view at 390px and 760px.
- [x] The audit above is done; all 52 findings are fixed.
- [x] Three tests guard the invariant, in `tests/css-cascade.test.mjs`.
- [x] No regression at 1440 / 1024.

## Review notes

The ticket named `.overview-grid` and guessed there would be more. There were 51 more, and
underneath them a second, unrelated cause. Both had to be fixed before the page stopped
scrolling sideways.

### Cause 1 — the whole responsive layer was dead

`app/globals.css` is five appended design layers, each ending with its own media queries:

| | plain rules | its media queries |
| --- | --- | --- |
| base | 1–236 | 237–270 |
| "Warm, clean visual direction" | 272–341 | 342–356 |
| "Legibility and unified icon-system pass" | 358–513 | 514–561 |
| "Final alignment and responsive QA fixes" | 563–612 | 613–638 |
| "Expanded commerce workspace" | 640–735 | 736–792 |

Each layer's plain rules sit **after** the previous layers' media queries, so they beat them
at every width. Only the last layer's media queries ever worked. 52 declarations across 34
selectors never took effect:

| breakpoint | dead declarations |
| --- | --- |
| ≤720px | 22 |
| ≤760px | 16 |
| ≤980px | 8 |
| ≤520px | 5 |
| ≤1080px | 1 |

**Fix:** every `@media` block moved to the end of the file, keeping its original relative
order, so later layers still refine earlier ones. This is a pure move — 973 declarations
before, 973 after, identical multiset. No value was edited.

### Cause 2 — a panel that could not shrink

Collapsing the grid was necessary but not sufficient: the document was still 744px wide.
`.today-main`'s single track was resolving to 716px because its grid items default to
`min-width: auto`, whose automatic minimum is the content's min-content width. The Today
view's channel table carries `min-width: 680px`, so the panel around it demanded 716px and
pushed the track, the layout and the document out with it.

The table already had `.table-scroll` (`overflow-x: auto`). It was never the problem. The
panel simply was not allowed to shrink around it. **Fix:** `.panel { min-width: 0 }`, written
once rather than per-layout. Three candidate fixes were tried in the live page first
(`min-width: 0` on the items, on `.panel`, and `minmax(0, 1fr)` on the track); all three
worked identically, and `.panel` was chosen because it states the invariant — a panel is
shrink-to-fit, content too wide for it scrolls inside it, and it never widens the page.

Every other view was already correct. Their rows are just as wide (`order-row` 720px,
`stock-row` 790px, `payout-row` 690px, `campaign-row` 610px) and they scroll inside their own
containers, which is why only Today overflowed.

### Measured after the fix

All 8 views driven through the sidebar at each width, 48 combinations, none overflowing.

| width | document | result |
| --- | --- | --- |
| 1440 / 1024 / 900 | equals viewport | clean |
| 760 | 760px | clean |
| 390 | 390px | clean |
| 360 | 360px | clean, checked below the agreed floor |

Before the fix: 744px at 390px, 772px at 760px. The channel table now renders 298px wide
with a 680px scroll width, so it scrolls inside its panel instead of the page.

Login page re-checked at 1440 / 1024 / 760 / 390 / 360: clean, mascot ratio held, no broken
images. Desktop compared by screenshot against the pre-change render: unchanged.

### Tests
`tests/css-cascade.test.mjs`, three guards, each falsified individually.

- *no media query is defeated by a later unconditional rule* — the audit itself, run as a
  test. Falsified by appending the `.overview-grid` rule that caused this ticket.
- *every media query stays at the end of the stylesheet* — catches the mistake one step
  earlier, when a plain rule is appended below the responsive layer but before it clashes
  with anything. Falsified with a rule that clashes with nothing; it still fails, as intended.
- *the panel that holds a wide table is allowed to shrink* — falsified by deleting
  `.panel { min-width: 0 }`.

### For PIN-0018
The warning in that ticket now has a mechanism behind it. Appending tokens or tone rules to
the end of `globals.css` will fail the second test, which is the point: the responsive layer
must stay last.
