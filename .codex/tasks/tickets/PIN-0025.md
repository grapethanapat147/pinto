# PIN-0025 — The channel connections screen

**Type:** Feature · **Phase:** 7 · **Status:** Done

Spec: `.codex/specs/channel-connections.md`. เกรพ asked for Shopee and TikTok Shop first, with
**the UI built ahead of the API work**.

## Scope
1. A ninth view, `connections`, wired into `View`, `navItems` and `viewTitles`.
2. One card per channel: real state from `channel_health`, last sync, one action.
3. A `channelProvider` seam mirroring `lineConfig()` — reports configured or not. Shopee and
   TikTok both report **not configured**, because they are.
4. Owner-only, enforced on the server.
5. The sidebar's existing "จัดการการเชื่อมต่อ" button navigates here instead of apologising.

## Explicitly not here
Token storage, OAuth callbacks, and any real marketplace call. See the spec's open questions —
token storage is a security decision that should not be made to satisfy a UI.

## Acceptance criteria
- [x] `connections` is reachable, and `View` / `navItems` / `viewTitles` stay synchronized.
- [x] Each channel card shows the state the database actually holds.
- [x] No control claims to connect anything — all five are disabled with their reason.
- [x] `staff` cannot reach the view or its data, enforced server-side.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` (49) pass.

## Review notes

### What the screen shows
Five channels in three groups, each with the state `channel_health` actually holds:

| channel | state | control |
| --- | --- | --- |
| Shopee | ปกติ | ยกเลิกการเชื่อมต่อ, disabled |
| TikTok Shop | ต้องตรวจสอบ | เชื่อมต่อใหม่, disabled |
| LINE MyShop | ปกติ | ยกเลิกการเชื่อมต่อ, disabled |
| Meta, TikTok Ads | ยังไม่เชื่อมต่อ | เชื่อมต่อ, disabled |

Every one disabled, each with its own reason: Shopee and TikTok name the missing credentials,
the rest say automatic connection is not supported for that channel. `providerStatus()` is the
`lineConfig()` pattern from PIN-0014, so when credentials arrive the buttons come alive and
`ConnectionsView.tsx` does not change.

### Three things this turned up

**The sync grid deliberately hides ad platforms**, because they have no stock to sync. The
connections screen wants them — a merchant connects an ad account the same way. Rather than a
second copy of the join, `listChannelHealth` gained an `includeAds` option defaulting to the
old behaviour, so the grid's existing test still guards it.

**The nav is rendered twice** and PIN-0013 shipped with Money filtered out of the sidebar and
still reachable in the mobile sheet. Adding a second owner-only view to two separate filters
would repeat that, so both now call one exported `isVisibleTo` predicate.

**The sidebar's upgrade card offered staff a door to nowhere.** Its "จัดการการเชื่อมต่อ"
button used to apologise; now it navigates, and for a staff member it navigated to a view that
renders nothing. The card is about profit accuracy, so it is owner-only.

### A raw timestamp reached the screen
The first render showed `ซิงก์ล่าสุด 2026-09-09T17:13:24.547Z`. Display strings are built in
the query layer (spec D3) and this one was passed straight through. It now uses
`formatMessageStamp`, and a test fails on an ISO stamp in the payload.

### Verified
All 8 views at 1440 / 1024 / 760 / 390: no horizontal overflow, no clipped text, five rows at
every width. On mobile the four-column row stacks rather than squeezing.

Staff, measured on the served HTML: 0 nav items, 0 connection rows in the payload, no provider
reason leaked, and no upgrade-card button. Owner gets all of it.

### Tests
Two tests, five guards, each falsified individually: pretending a provider is configured,
dropping the timestamp formatting, removing `connections` from the owner-only list, sending
the data to staff, and showing staff the upgrade card.

The first test asserts on the **payload** rather than the markup, because this is a client
view and its HTML is not in the first response. That is the stronger assertion anyway — the
payload is what the buttons derive from, so it cannot be right there and wrong on screen. It
counts `"connectable":true` and requires zero, so adding a channel cannot quietly ship a live
button.
