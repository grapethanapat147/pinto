### The manifest problem, and what the assertion caught
`dist/server/wrangler.json` is regenerated by every build and carries `vite.config.ts`'s
local placeholder D1. The real id therefore cannot live there.

The first attempt put a `wrangler.json` at the repo root. **`@cloudflare/vite-plugin`
auto-discovers that filename and merged it into the generated manifest**, producing two D1
entries on the same `DB` binding — an ambiguity that would have deployed something nobody
chose. `scripts/deploy.mjs` refused to proceed and said why, which is exactly what its
shape assertions exist for.

Renaming the file to `wrangler.deploy.json` takes it out of the plugin's sight. It is passed
explicitly with `-c` to the deploy and to every `wrangler d1` command, so the database id has
one home. `vite.config.ts` was never touched, and the local database still holds its 3 users
and 15 sessions.

### Migrations
Applied with `wrangler d1 migrations apply pinto --remote`, all six ✅. The same six had
already been rehearsed against a throwaway local database while writing the spec, so this
was confirmation rather than a gamble.

## The original plan, for reference

1. **Was the artifact accepted?** A deployment exists and the URL loads something.
2. **Were migrations applied?** Load the URL. Two outcomes, and both are informative:
   - The login page renders → tables exist, migrations ran.
   - `DataUnavailable` renders → no tables. PIN-0008's fallback gets its first real
     exercise, and Q3 needs a different answer.
3. **Was a real `DB` binding injected?** If the page renders at all, `db/index.ts` did not
   throw, so the binding is real and not the placeholder.
4. **Can anything be signed in as?** Expected: **no.** The database is empty, so the demo
   button should 500 with `demo user demo-owner is not seeded` — an honest message, and the
   thing PIN-0021 fixes.
5. **Are the brand assets served?** `/pinto/logo-lockup.svg`, `/pinto/favicon.svg`, and the
   OG image at its absolute URL.
6. **Is LINE Login correctly disabled?** Expected: yes. No secret can reach production, so
   `lineConfig()` returns null and the page says LINE is not connected. A live-looking LINE
   button in production would be a bug.
