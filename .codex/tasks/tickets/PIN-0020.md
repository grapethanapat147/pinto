# PIN-0020 — First deploy: prove the pipeline

**Type:** Chore · **Phase:** 6 · **Status:** In Progress

Spec: `.codex/specs/deploy.md`. เกรพ chose **(a)**, a shareable demo.

This ticket exists to answer **Q4 — are migrations applied on deploy?** Nothing else can be
designed until that is known, because if there are no tables there is nothing for a seed to
write into. So this deliberately ships as little as possible and then goes and looks.

**I cannot deploy.** There is no CLI and no deploy script; the Sites control plane is
เกรพ's to press. My half is making the artifact identifiable and correct, and knowing exactly
what to check afterwards.

## Scope

1. **Rename off the template.** `package.json` is `site-creator-vinext-starter`, and the
   generated `dist/server/wrangler.json` inherits it as the worker name. That is the name
   that will appear in the hosting dashboard and in every log line. Rename to `pinto`, and
   check the generated manifest picks it up rather than assuming it does.
2. **Nothing else.** No seed, no secret plumbing, no dependency bumps. Each of those wants
   the answer to Q4 first.

## What เกรพ does
Deploy the current `main` through the Sites control plane, then send back the URL.

## What is then checked, in this order
Each answer changes whether the next question is even worth asking.

1. **Was the artifact accepted?** A deployment exists and the URL loads something.
2. **Were migrations applied?** Load the URL. Two outcomes, and both are informative:
   - The login page renders → tables exist, migrations ran.
   - `DataUnavailable` renders → no tables. PIN-0008's fallback gets its first real
     exercise, and Q3 needs a different answer.
3. **Was a real `DB` binding injected?** If the page renders at all, `db/index.ts` did not
   throw, so the binding is real and not the placeholder.
4. **Can anything be signed in as?** Expected: **no.** The database is empty, so the demo
   button should 500 with `demo user demo-owner is not seeded` — an honest message, and the
   thing PIN-0021 fixes.
5. **Are the brand assets served?** `/pinto/logo-lockup.svg`, `/pinto/favicon.svg`, and the
   OG image at its absolute URL.
6. **Is LINE Login correctly disabled?** Expected: yes. No secret can reach production, so
   `lineConfig()` returns null and the page says LINE is not connected. A live-looking LINE
   button in production would be a bug.
