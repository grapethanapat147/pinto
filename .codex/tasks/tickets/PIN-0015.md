## The three defects, re-verified today
Milestone 4 changed a lot of this code; all three survive.

**F1** — `db/queries.ts` lines 64, 152 and 187 each re-derive a channel's short name.
The `: "TikTok"` fallback means **any unrecognised channel silently renders as TikTok**.

**F2** — `InboxView` (×2), `OrdersView` and `TodayView` recover the logo class by sniffing
display text: `channel.toLowerCase()`, `payout.platform.startsWith("TikTok")`. Rename a
channel and the colour silently goes.

**F3** — `StockView`'s sync grid is three literal blocks with hardcoded
"ซิงก์ล่าสุด 1/2/4 นาทีที่แล้ว" and three identical "ปกติ" pills. It cannot ever show a real
problem, which is the one thing a sync indicator exists to do.

## Scope
Narrow, per the spec's caveat that an interface with no real implementation is designed
against guesses:

- one channel resolver, keyed by `channels.code`, that **throws on an unknown code**
- an `accent` column so the logo class is data, not a guess from a label
- a `channel_health` table and the sync grid reading it
- a `ChannelAdapter` type plus a demo adapter over seeded data, so the interface is
  exercised by real code rather than being aspirational

Out until a real integration asks: fulfilment, label printing, price/stock push, campaign
management, payout reconciliation.

"1 นาทีที่แล้ว" forever. Ad platforms are filtered out — they have no stock to sync.

### A bug I introduced and caught
The first version printed **"ยังไม่ได้เชื่อมต่อช่องทางนี้" under a healthy channel**: the
fallback fired whenever `detail` was null, but a healthy row legitimately has no detail.
"No health row" and "null detail" are different facts and were being conflated. Only the
missing-row case falls back now.

### Two harness bugs the new tests exposed
1. The digest test ran `UPDATE sessions SET expires_at = ...` **unscoped**, expiring every
   session including the shared one. Later tests using bare `render()` had been running
   unauthenticated and passing anyway — nothing had noticed until a new test rendered.
2. Scoping it by `rows.at(-1).id` was still wrong: `SELECT` has no ordering, so it could
   pick the shared session again. The digest is now derived from the token under test.

The fixed test also asserts other sessions survive, so an unscoped update cannot come back.

`tests/support/resolve-hooks.mjs` gained extensionless `.ts` resolution, which is what lets
a test import `db/*.ts` directly — the channel resolver is now unit-tested rather than only
observed through HTML.

### Scope kept narrow, deliberately
`ChannelAdapter` has one method, `health()`, because that is the only channel operation the
app performs. The spec sketched `listOrders`/`sendMessage`; adding methods no implementation
calls is the guesswork it warned against, so the type comment was corrected to say so
rather than describing a method that is not there.

`inventory_levels.sync_state` is untouched (Q2 → narrow). Its own ticket when something
reads it as more than a label.
