# PIN-0006 — Read path: actions, conversations, campaigns, payouts

**Type:** Feature · **Phase:** 2 · **Status:** Done

Spec: `.codex/specs/persistence-foundation.md` (D3). PIN-0005 proved the architecture on
orders and inventory; this converts the rest.

## Goal
Move the four remaining domains off `app/fixtures/`. After this, no view imports fixture
*data* — only `navigation.ts`, which is UI configuration (nav items, page titles), not
records, and stays.

## Schema gap found first
`conversations.preview` is **not derivable** from the messages, so schema-v1 was wrong to
omit it. Checked all four fixtures: previews 1 and 2 equal the last message, but 3 is a
truncation and 4 is different text entirely ("ต้องการใบกำกับภาษีค่ะ" vs the message
"รบกวนออกใบกำกับภาษีในนามบริษัทได้ไหมคะ"). It is editorial summary text.

Fixed with a second migration adding the column — `ALTER TABLE ADD COLUMN` is additive,
so it stays inside the spec Q4 rule.

## Derived on read, not stored
- campaign ROAS = `revenue_satang / spend_satang`, two decimals (schema-v1 F2)
- action `impact` string rebuilt from `impact_kind` + `impact_satang`
- action `source` rebuilt from `detected_at` as "อัปเดต HH:MM น."
- message stamps render "HH:MM" for today and "เมื่อวาน" for the previous day, which
  reproduces the fixture's mixed display and is more correct than a frozen string
- Action Center total = `SUM(impact_satang) WHERE resolved_at IS NULL` (spec Q3) — this
  is where ฿22,990 stops being a literal and starts dropping when an action is resolved

### schema-v1 was wrong about `preview`
Caught before writing the query, by checking all four conversations rather than the first
one: previews 1 and 2 equal the last message, so a derive-from-messages approach would
have looked correct in testing and been wrong in production. Preview 3 is a truncation and
preview 4 is entirely different text. Fixed with migration `0001_bent_wind_dancer`, a
single `ALTER TABLE ADD COLUMN` — additive, so still inside the Q4 rule.

Verified live: the tax-invoice thread shows preview `ต้องการใบกำกับภาษีค่ะ` in the list
while its message body reads `รบกวนออกใบกำกับภาษีในนามบริษัทได้ไหมคะ`.

### ฿22,990 is now real
Resolving the first action takes the headline from **฿22,990 to ฿19,750** — exactly minus
the 3,240 that was resolved — with the heading going 4 → 3 and the list dropping a row.
That is the drift found in the schema audit, actually fixed.

`ShopAction` gained an optional `impactSatang` so the client can sum open actions as they
resolve. Optional because the fixtures feed the seed and need not restate a number the
display string already carries.

### A bug in my own migration runner
`db:local:reset` replayed every migration every time, so the second run tried to
`CREATE TABLE` over live tables. Added an `_applied_migrations` table; runs now report
`applying` once then `skipping`. The local database had 0000 applied before tracking
existed, so it was deleted and rebuilt from scratch rather than hand-patching the tracker
into a consistent state — it holds nothing but seed output.
