# PIN-0003 — Schema and first migration

**Type:** Feature · **Phase:** 2 · **Status:** Done

Specs: `.codex/specs/persistence-foundation.md`, `.codex/specs/schema-v1.md`
(all three schema-v1 questions resolved 2026-09-08).

## Goal
Turn `db/schema.ts` — today an empty stub — into the real data model, and generate the
first migration. `drizzle/meta/_journal.json` still has `"entries": []`; no migration has
ever existed in this repo.

No seed, no query, no UI change. Those are PIN-0004 onwards.

## Scope
**Domain (10 tables):** `shops`, `channels`, `products`, `inventory_levels`, `orders`,
`conversations`, `messages`, `actions`, `campaigns`, `payouts`.

**Presentation scaffolding (5 tables)** — per resolved Q1(c), so the 41 hardcoded figures
become data rather than JSX literals: `dashboard_metrics`, `customer_segments`, `regions`,
`waterfall_steps`, `restock_suggestions`, `product_opportunities`.

These are explicitly temporary: the later aggregation ticket replaces most of them with
queries over the domain tables. They are grouped separately in `db/schema.ts` and labelled.

## Acceptance criteria
- [x] `db/schema.ts` defines the tables above with Drizzle sqlite-core.
- [x] Money is `INTEGER` satang everywhere — no text, no float.
- [x] Timestamps are ISO-8601 text (resolved Q2).
- [x] Every table has a non-null `shop_id` (spec D5).
- [x] `roas`, inventory `status`, the action total and the active-action count are **not**
      columns — they stay derivable (schema-v1 F2).
- [x] Foreign keys declared: inventory→products, orders→channels, conversations→channels
      and →orders, messages→conversations, campaigns/payouts→channels.
- [x] `npm run db:generate` produces exactly one migration; `_journal.json` gains 1 entry.
- [x] The generated SQL is **additive only** — no `DROP`, no destructive `ALTER`
      (spec Q4: migration-on-deploy is unverified and has no rollback).
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` all pass.
- [x] The running app is untouched — it still reads fixtures and renders identically.

## Review notes

gained its first entry ever: `0000_loud_albert_cleary`.

**10 domain tables** — shops, channels, products, inventory_levels, orders,

Verified on the generated SQL, not asserted:
- **Additive only.** Statement census: 17 `CREATE TABLE`, 7 `CREATE UNIQUE INDEX`,
  6 `CREATE INDEX`. Zero DROP/ALTER/DELETE/TRUNCATE. (A first grep appeared to find
  destructive statements — it was matching `ON DELETE no action` inside foreign-key
  clauses. Checked again anchored to line starts.)
- **It runs.** Piped into a throwaway sqlite file: applies cleanly, 17 tables created,
  `pragma foreign_key_check` reports no violations. So table creation order and every FK
  target resolve.
- **Money is integer satang** — 10 `*_satang integer` columns, zero money columns typed
  REAL or TEXT.
- **`shop_id` on all 16 non-`shops` tables**, checked by parsing each CREATE TABLE body.
- **Derived values absent** as designed: no `roas`, no inventory `status`, no stored
  action total or open-action count.

Deliberate modelling calls, each recorded inline in `db/schema.ts` so the reasoning
survives: products split from inventory_levels; a `channels` table to canonicalise the
four spellings of TikTok; `actions.channel_label` left free text because "Shopee + TikTok"
is two channels; `days_left` stored and flagged denormalised for want of velocity data;
`external_id` keeping TT-10842 marketplace-facing while the PK stays internal.

`app/` has **zero** changes — `git status` on that path is empty. The running app still
reads fixtures: a fresh tab shows ฿48,720, 8 nav items, badge 4, no console errors.
