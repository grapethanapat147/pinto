# PIN-0018 — Design tokens and the quiet-chrome tone pass

**Type:** Feature · **Phase:** 5 · **Status:** Review

The half of the design system PIN-0017 deliberately left alone. PIN-0017 installed the
artwork; this applies the rules that go with it. Reference: `Pinto-New-Design/` —
`design-tokens.css`, `tokens.json`, `HANDOFF.md`, and `dashboard-preview.png`, which is the
delivered picture of what "quiet chrome" means on Pinto's own Today screen.

## Scope
1. **Tokens.** Merge `design-tokens.css` into `app/globals.css`. Rename `--green`, which
   already holds an orange, to `--brand`, then check every reference before deleting the
   leftover vinext `:root`. The handoff is explicit that `tokens.css` must **not** replace
   `globals.css` wholesale — it carries the guide's own page styles.
2. **Tone.** Cards white on `#F5F0EC`, 1px `#EBE4DF` border, radius 8px, **no shadows**.
   Buttons radius 7px; secondary buttons are plain text. Large numbers weight 600. Change
   deltas are plain text, not pills. Roughly four orange elements per screen.
3. **Type and spacing.** Base 15px / 1.55. Spacing scale 4/8/12/16/20/24/32.
4. **Icons.** Lucide 18–21px, stroke 1.9. Tap targets at least 44px with a visible focus ring.

## Open decisions
- **`.brand-sub` ("Commerce Center").** Added in PIN-0017; the delivered
  `dashboard-preview.png` shows the lockup alone with no sub-label. Keep it or drop it.
- **Contrast.** The handoff flags that `--soft` and some status pairs fail contrast for small
  text. Decide where `--ink` must be used instead, and make sure colour is never the only
  carrier of meaning.
- **Empty states.** The delivered guide uses `mascot-bust.svg` on its empty state.
  `DataUnavailable` is an outage page rather than an empty list, so it currently shows the
  logo mark. Decide whether Pinto's genuine empty lists should carry the mascot.

## Warning carried over from PIN-0017
`app/globals.css` is a stack of appended override layers, and **media queries add no
specificity**. Any token or tone rule appended at the end will beat every media query above
it. PIN-0019 exists because that already happened to `.overview-grid`. Do PIN-0019's audit
first, or do it as part of this ticket.

## Review notes

### What the two `:root` blocks were actually doing

The stylesheet had the vinext template's **green** palette at the top and an orange block 235
lines below it that overrode only the six values it cared about. Everything the second block
never mentioned was still the template's — the status colours, white, and the focus ring,
which drew **green** on an orange UI at `rgba(20, 115, 86, .18)`.

The names lied as well. `--green` held `#c85410`, an orange, and was doing double duty as
both the brand accent **and** the success colour. That is why every positive number on the
dashboard was orange: the accent budget was being spent on decoration. The delivered system
separates them, so `--success` `#658b39` now carries positive states and orange is reserved
for what the merchant should act on.

### The token merge was proved neutral, the palette pass measured

The rename and the single `:root` had to change nothing on screen, so it was checked rather
than assumed: a fingerprint of seven computed properties for every element across all eight
views, 2999 rows, **zero differences**. The same check ran again after the 25 exact
hex-to-token substitutions: zero differences.

Collapsing near-duplicate colours onto the palette did change pixels, by design. 148 of 2983
rows changed, all of them colour-only, largest shift 16 per channel — the region progress
groove moving off a cool grey onto `--line`.

**A first attempt at that pass was wrong and was reverted.** Matching on total channel
distance alone mapped two neutral greys onto `--success-soft`, which would have tinted the
default and demo status pills green. The rule now also compares saturation and hue, so a
near-grey may only collapse onto another near-grey. Seven colours it correctly refused were
then mapped by role instead, and the three channel-brand grounds (TikTok, LINE, Meta) were
deliberately left alone — a platform's own colour is not a palette violation.

### Tone

Cards are `--radius-card` and buttons `--radius-button`; 58 radius declarations across 52
selectors were rewritten from 22 ad-hoc values down to 13. All 14 drop shadows are gone.
Three of them were not elevation and were kept in another form: the live dot's halo ring was
restored, and the toast and the mobile sheet, which float with nothing behind them, now use a
1px line instead.

Large numbers carry weight 600. Change figures are no longer pills — the delivered
`dashboard-preview.png` shows `+12.4% จากเมื่อวาน` as plain grey text, and a pill beside every
number was both off-system and spending orange on decoration.

Orange now appears in **four** groups on the Today screen: the chart bars, the primary
button, the profit legend key, and the selected calendar day. The handoff asks for about four.

Controls follow the delivered `tokens.css`: `min-height: 44px` on buttons and inputs, and a
secondary button is plain text rather than a second outlined box competing with the primary.
Compact segmented controls — period tabs, filter chips, calendar cells — keep their own
height; they are not `.btn` and the guide sizes them separately.

### Contrast

Measured on the rendered page, every text node against its real background.

| | failing elements |
| --- | ---: |
| before | 41 |
| after | 12 |

The fix followed the handoff's own instruction rather than changing the palette: `--soft` is
2.77:1 on white and now carries no text at all, only decoration. 27 `--soft` declarations and
14 hard-coded low-contrast greys moved to `--muted` (4.93:1 on white).

**What still fails, and why it is staying:**

- `.status-pill.good` at 3.52:1 — this is the delivered system's own `.status-success`
  pairing of `--success` on `--success-soft`. The handoff flags it and says to pair colour
  with words; every pill carries a word, so meaning never rests on colour alone.
- The channel letters at 3.39 and 3.60:1 — each platform's own brand colour, with the channel
  name written beside it.
- `--muted` on `--canvas` at 4.36:1 and `--brand` at 4.44:1 — both within 3% of the threshold
  and both fixed by the brief.

Changing any of these means changing the delivered palette, which is เกรพ's call, not a
silent edit here.

### The three open decisions

1. **`.brand-sub` "Commerce Center" — removed.** The delivered `dashboard-preview.png` shows
   the lockup alone, and at 8px in `--soft` it was the single worst contrast on the page. It
   was my addition in PIN-0017, not part of either delivery. One line to restore if wanted.
2. **Contrast — handled as above**, by reserving `--soft` for decoration rather than by
   editing the palette.
3. **Empty states — the mascot stays off them.** The delivered guide puts `mascot-bust.svg`
   on a "เริ่มรับออเดอร์แรกของคุณ" onboarding empty. Pinto's `EmptyState` is used in seven
   places and mostly means *filtered to zero* — "ไม่พบออเดอร์", "ไม่พบสินค้าในหมวดนี้" — rendered
   inline inside a panel. A 240px illustration there would be noise, repeated. The mascot
   greets once, on login.

### Tests

`tests/design-tokens.test.mjs`, five guards, each falsified individually by reintroducing the
exact defect it protects against: a second `:root`, a template token name, a palette value
drifted from the delivered file, a drop shadow, and the green focus ring.

`.codex/specs/design-system/` holds `design-tokens.css`, `tokens.json` and `HANDOFF.md`
copied verbatim from the delivery, and the palette test compares the app against that file
rather than against numbers retyped into a test. It earned its place immediately: it caught
`var(--amber-soft, var(--warning-soft))`, a reference the rename had missed because the
regex required a closing parenthesis and this one had a fallback argument.

Suite: 35/35.
