# PIN-0028 — Edit unit cost on the Stock view

**Type:** Feature · **Phase:** 9 · **Status:** Done

Spec: `.codex/specs/cost-and-profit.md`, Q4 and Q5.

## Scope
1. An inline cost field per product row on Stock, owner only.
2. A write endpoint that validates, scopes to the session's shop, and persists.
3. Editing a cost changes **future** order lines only — the snapshot means history is not
   rewritten, and that is tested.
4. The Today view's "เพิ่มข้อมูลต้นทุน" button goes to this instead of apologising.

## Open question found in PIN-0027 — ask before building
Coverage is computed from the **line snapshots**, not from `products.unit_cost_satang`. So
costing ผ้าปูโต๊ะ Linen Sand today lifts coverage only for orders placed from now on; every
past line keeps its null cost and the 30-day figure stays partial for a month. That is the
snapshot design working as intended — but a seller entering a missing cost will expect the
warning to go away.

Filling a **null** snapshot with the first known cost is arguably not rewriting history
(there was no cost to rewrite), whereas changing a non-null one is. Options: (a) offer a
one-time "apply to past orders that had no cost" when a cost is first set; (b) leave history
alone and explain it on screen. Needs เกรพ's call.

**Decided 2026-11-03 (daily-brief spec Q8): option (a).** When a product's cost is first set,
offer once to fill it into past lines whose cost is null. Lines that already have a cost are
never changed.

Also: the Money view's new "เพิ่มต้นทุนสินค้า" button (PIN-0027) should open this too.

## Acceptance criteria
- [x] `staff` cannot see the cost column or write to the endpoint — server-side.
- [x] An unauthenticated write is rejected before touching the database.
- [x] Changing a cost does not change any existing order line's cost — tested.
- [x] Invalid input (negative, non-numeric, absurdly large) is refused with a message.
- [ ] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.

## Review notes

### What changed
- **Stock view:** a "ต้นทุน/ชิ้น" column for owners, edited in place. A product with no cost
  shows "ยังไม่มี · ใส่ต้นทุน"; one with a cost shows it and "แก้". Saving refreshes the page's
  server data (`router.refresh()`), so profit, coverage and the brief update without leaving
  Stock.
- **`POST /api/products/[sku]/cost`:** 401 without a session, 403 for staff, 400 with a Thai
  message for anything that is not a cost (negative, zero, `1e3`, `250,00`, three decimals,
  over ฿1,000,000, empty), 404 for an unknown SKU, 409 for a second "fill past lines".
- **Spec Q8, the one-time fill:** when a product has no cost yet and past lines are uncosted, a
  checkbox (ticked by default) says how many lines it will fill. Lines are filled before the
  product is updated, and only while the product is still uncosted — so a retry can never fill
  twice, and a half-finished write cannot leave lines filled with a different cost.
- **Cost never reaches staff:** `listInventory` only adds `cost` for owners; staff's payload
  has no cost field at all.
- "เพิ่มข้อมูลต้นทุน" on Today (now owner-only) and "เพิ่มต้นทุนสินค้า" on Money go to Stock
  instead of a "not available yet" notice.
- Stock rows are `div`s, not `button`s: a form cannot sit inside a button, and the row click
  only ever showed "หน้ารายละเอียดยังไม่เปิดใช้งาน".

### Found and fixed while verifying
1. **The page grew to 575px wide on a phone** while the cost editor was open. The
   visually-hidden label is `position: absolute` with no positioned ancestor, so it escaped
   the scrolling table and widened the document. The deployed site (no editor) measured 390,
   which isolated it. `.cost-cell` is now the containing block.
2. **The stock table already scrolled sideways at 1440** (790px of columns in a 711px panel —
   pre-existing), and focusing the new field scrolled the product names out of view. The name
   column is now pinned on wide screens, the editor scrolls itself to the middle of the table,
   and on ≤760px the pin is off (a 220px pinned column would leave a phone nothing to scroll).

### Verification
- 68/68 tests; tsc and lint clean. New tests: owner/staff payload, every refusal leaves costs
  unchanged, a changed cost leaves every existing line's snapshot as it was, the first cost
  fills exactly the uncosted lines and coverage reaches 100% with the brief's cost card gone,
  and a first cost without the fill leaves history alone.
- Falsified 8 ways — staff allowed to write, `1e3` accepted, zero accepted, history rewritten,
  fill allowed twice, cost leaking to staff, fill ignoring the owner's choice — all caught.
  (A first, weaker "rewrites history" mutation was missed because the null-only guard still
  held; a real rewrite was then caught by the snapshot test.)
- Live, by keyboard: "-5" refused with its message and `aria-invalid`; ฿240 on Linen Sand
  with the fill → "เติมให้ออเดอร์เก่า 3,338 รายการ", the database had 0 uncosted lines, the
  brief badge went 6 → 5, Today's coverage label disappeared and profit fell to ฿30,408 as the
  linen's cost was deducted. Local data restored afterwards so the demo stays partly costed.
- 1440 / 1024 / 760 / 390 with the editor open: page width equals the viewport, the editor is
  inside the table and clear of the pinned names, focus lands in the field.

### Production (2026-11-03)
- Deployed (version `d33e13cd`), no migration needed. Live: Today's "เพิ่มข้อมูลต้นทุน" opens
  Stock; the cost column shows ฿250 / ฿600 / ฿350 / ยังไม่มี / ฿185; Linen's editor offers to fill
