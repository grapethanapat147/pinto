# PIN-0028 — Edit unit cost on the Stock view

**Type:** Feature · **Phase:** 8 · **Status:** Backlog · **Blocked by:** PIN-0026

Spec: `.codex/specs/cost-and-profit.md`, Q4 and Q5.

## Scope
1. An inline cost field per product row on Stock, owner only.
2. A write endpoint that validates, scopes to the session's shop, and persists.
3. Editing a cost changes **future** order lines only — the snapshot means history is not
   rewritten, and that is tested.
4. The Today view's "เพิ่มข้อมูลต้นทุน" button goes to this instead of apologising.

## Open question found in PIN-0027 — ask before building
Coverage is computed from the **line snapshots**, not from `products.unit_cost_satang`. So
costing ผ้าปูโต๊ะ Linen Sand today lifts coverage only for orders placed from now on; every
past line keeps its null cost and the 30-day figure stays partial for a month. That is the
snapshot design working as intended — but a seller entering a missing cost will expect the
warning to go away.

Filling a **null** snapshot with the first known cost is arguably not rewriting history
(there was no cost to rewrite), whereas changing a non-null one is. Options: (a) offer a
one-time "apply to past orders that had no cost" when a cost is first set; (b) leave history
alone and explain it on screen. Needs เกรพ's call.

Also: the Money view's new "เพิ่มต้นทุนสินค้า" button (PIN-0027) should open this too.

## Acceptance criteria
- [ ] `staff` cannot see the cost column or write to the endpoint — server-side.
- [ ] An unauthenticated write is rejected before touching the database.
- [ ] Changing a cost does not change any existing order line's cost — tested.
- [ ] Invalid input (negative, non-numeric, absurdly large) is refused with a message.
- [ ] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.
