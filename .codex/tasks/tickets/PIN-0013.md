# PIN-0013 — Roles: staff cannot read finance

**Type:** Feature · **Phase:** 4 · **Status:** Review

Spec: `.codex/specs/auth-and-roles.md`. The `role` column already exists on `users`
(PIN-0011) and the session already carries it to the query layer (PIN-0012); nothing reads
it yet.

## Where the line goes
`owner` sees everything. `staff` loses **money movement**, not operational performance:

| Hidden from staff | Kept for staff |
| --- | --- |
| the Money view entirely — profit hero, withdrawable balance, waterfall, payout table | today's profit and sales figures |
| TodayView's "เงินที่กำลังจะเข้า" payout rail | orders, inbox, stock, customers, growth |

A packing assistant has no business seeing payout accounts or the withdrawable balance.
Stripping *all* profit would gut the dashboard — the product's whole premise is seeing
whether the day made money — so the line is money **movement**, not performance.

## Enforced by absence, not by hiding
`staff` finance queries are never run, so the data never reaches the client. `AppShell` is
a client component, so anything sent to it is readable however the nav is drawn — hiding a
menu item would not be enforcement.

## Demo value
A second demo button signs in as staff, so the role difference can be **shown to a client
live** rather than described. Same reasoning as the one-click owner sign-in.

## Acceptance criteria
- [x] A seeded `demo-staff` user with role `staff`.
- [x] Login page offers owner and staff demo sign-in, clearly labelled.
- [x] For `staff`: no Money nav item, no payout rail, and Money renders nothing useful
      even if reached by manipulating client state.
- [x] Finance data is absent from the served payload for staff — verified by searching the
      HTML, not by looking at the screen.
- [x] `owner` is unchanged.
- [x] Tests cover both roles and assert the payload difference.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.

## Review notes

### The payload, not the screen
Compared what the server actually sends to each role:

| | owner | staff |
| --- | --- | --- |
| Money nav item | present | **absent** |
| payout `฿38,740` | present | **absent from the HTML** |
| withdrawable `฿24,680` | present | **absent** |
| waterfall `฿126.8k` | present | **absent** |
| orders `TT-10842` | present | present |
| today's profit `฿48,720` | present | present |

Staff finance queries are never run and the money tiles are deleted from the metrics
bundle before serialisation, so there is nothing to find however the client is
manipulated. Hiding a nav item would not have been enforcement — `AppShell` is a client
component, and anything sent to it is readable.

The nav filter and the route guard are belt and braces on top of that, not the mechanism.

### A false alarm worth recording
The first check reported staff still seeing `การเงิน`. Searching for where it actually
occurred found `"topic":"เอกสารการเงิน"` — a conversation subject in the inbox, which staff
are supposed to see. The regex was too loose, not the code. Re-checked by extracting the
rendered `<em>` nav labels: owner has 8 entries, staff has 7.

Worth the two minutes — the opposite mistake, a loose assertion that passes, would have
shipped a hole.

### A gap the first pass missed
`AppSidebar` was filtered but `MobileMoreSheet` renders its own copy of `navItems`, so on
a phone staff could still have tapped through to Money. Filtered there too.

### Where the line sits, and why
Staff lose money **movement** — payouts, withdrawable balance, the waterfall — and keep
today's profit and sales. Stripping all profit would gut the dashboard, whose whole premise
is seeing whether the day made money. A packing assistant seeing revenue is normal; seeing
the bank position is not.

### Demo value
A second one-click button signs in as staff, so the difference can be **shown** to a client
rather than described. `?as=` accepts only the two seeded identities — `?as=admin` is 400,
so the parameter cannot mint a role that was never seeded.

Verified in the browser: staff sees 7 nav items with no การเงิน, no payout rail, and
`฿48,720` still on the Today view, signed in as `คุณฟ้า (พนักงาน)`.
