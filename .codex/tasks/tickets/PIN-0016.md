# PIN-0016 — Normalise per-channel stock sync

**Type:** Feature · **Phase:** 3 · **Status:** Done

The wide half of `.codex/specs/channel-adapters.md` Q2, deferred out of PIN-0015.

## The problem
`inventory_levels.sync_state` holds Thai prose — `ครบ 3 ช่องทาง`, `TikTok รออัปเดต` — a
per-channel fact flattened onto the product. Nothing can ask "is this product synced to
Shopee?", which is the question the column exists to answer.

## And a duplication PIN-0015 introduced
That column and `channel_health` currently state the same fact at two granularities:

```
inventory_levels : ML-CL-006 -> "TikTok รออัปเดต"
channel_health   : TikTok Shop -> degraded, "สต๊อกบางรายการรออัปเดต"
```

They agree today by coincidence. Nothing keeps them agreeing, and seeding both is how a
dashboard ends up contradicting itself. Normalising is the chance to make one derive from
the other rather than leaving two hand-maintained copies.

## Design
`inventory_channel_sync` — one row per product per channel, with a state and a timestamp.

Two things then become derived rather than stored:
- the product's sync label: all synced → `ครบ N ช่องทาง`; otherwise `<channel> รออัปเดต`,
  which reproduces both existing strings exactly
- a channel's **stock** detail in the sync grid: `สต๊อกบางรายการรออัปเดต` computed from the
  count of pending products, not seeded prose

`channel_health` keeps `state` — connection health is a separate fact from stock currency,
and a disconnected channel is not the same as a behind-on-stock one.

## `sync_state` stays as a dead column
Migrations are additive only (spec Q4) because migration-on-deploy is still unverified and
has no rollback. Nothing will read it after this; dropping it needs that question answered
first. Marked deprecated in the schema so it is not mistaken for live.

## Acceptance criteria
- [x] `inventory_channel_sync` via an additive migration; 5 products × 3 channels seeded.
- [x] The stock table's sync column is derived, and reproduces `ครบ 3 ช่องทาง` and
      `TikTok รออัปเดต` exactly.
- [x] The sync grid's stock detail is derived from pending rows, not seeded prose.
- [x] Nothing reads `inventory_levels.sync_state`; it is marked deprecated.
- [x] Tests cover the derivation, including a product pending on more than one channel.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.

### The duplication is gone
`inventory_levels.sync_state` and `channel_health.detail` were two hand-seeded copies of
one fact. The channel's stock detail is now counted from the same rows the product label
reads, so TikTok reports degraded *because* exactly one product is behind on it. Seeding
one without the other can no longer make the dashboard contradict itself.

`channel_health.state` stays — connection health is a genuinely separate fact, and a
disconnected channel is not the same as a behind-on-stock one.

### The multi-channel case needed its own test
The seed has one product pending on one channel, so it cannot exercise the branch that
lists several. The new test drives a product to pending on Shopee, then on TikTok too, and
asserts `TikTok, Shopee รออัปเดต` — then **restores the rows**, because that state is shared
with every other test in the file.

### A PIN-0015 test had to change
It asserted the exact seeded sentence. That sentence is now computed, so the assertion
moved to the shape (`/^สต๊อก \d+ รายการรออัปเดต$/`) rather than the literal — an expected
consequence of this ticket, not a regression.

### `sync_state` is deprecated, not dropped
Nothing reads it (`grep syncState db/queries.ts` → 0). Migrations are additive only
(spec Q4) because migration-on-deploy is still unverified with no rollback, so the column
stays and is marked `@deprecated` in the schema. Dropping it needs that question settled.
