# PIN-0009 — Seed the presentation tables and wire the metric tiles

**Type:** Feature · **Phase:** 2 · **Status:** Review

Specs: `.codex/specs/persistence-foundation.md`, `.codex/specs/schema-v1.md` (resolved Q1(c)).

## Goal
41 figures are still hardcoded in `app/components/*.tsx`, so the dashboard's headline
numbers are literals that no query can ever agree with. Move them into the 7 presentation
tables PIN-0003 created and read them back.

Q1(c) chose this over deriving them, and that was right for this dataset: the demo has 6
orders but the tiles say 284. Deriving would collapse the dashboard to demo-sized numbers
and make it look emptier, not more honest. Deriving is the later ticket, once there is
enough data behind it.

## Approach
- `app/fixtures/metrics.ts` holds the transcription, so it is reviewable in one place and
  the seed stays fixture-driven (spec D2).
- One `metrics` prop object rather than nine new props threaded through the tree.
- Values stored as numbers with a unit, formatted on read — same rule as everywhere else.

## Derived, not stored
- channel margin = `profit / sales` (verified: 36.4% / 39.7% / 43.4% reproduce exactly)
- waterfall labels abbreviate from the stored satang (126840 → `฿126.8k`)

## Also
TodayView's payout rail restates the `payouts` table — same three platforms, counts and
amounts. It reads from the real query instead of being seeded a second time.

### Three things are now derived rather than stored
- **Channel margin** = profit / sales → 36.4% / 39.7% / 43.4%, matching exactly.
- **Region bar widths** — the fixture's 100 / 38 / 28 / 22 / 19 turned out to be the share
  percentages normalised against the largest. Verified the arithmetic reproduces all five,
  so the widths are computed and only the shares are stored.
- **Waterfall labels** abbreviate from satang: 12684000 → `฿126.8k`, and the sign comes
  from `kind` rather than being part of the text.

### TodayView's payout rail
It restated the payouts table — same three platforms, counts and amounts. Now reads the
real query, so it shows `พรุ่งนี้ · 142 ออเดอร์ · ฿38,740` with the later two dated from the
seed anchor. One less place for the same number to disagree with itself.

### One acceptance criterion is NOT met
Three "Pinto แนะนำ" advisory panels still contain hardcoded amounts: ฿46,700 (customer
segment value), ฿1,200 and ฿2,080 (budget shift), ฿24,600 (restock cost).

Left deliberately. Each sits inside a Thai advisory sentence — "โยกงบ ฿1,200 ไปที่ Ceramic
Set", "ใช้เงินเพิ่มไม่เกิน ฿24,600". Extracting the number while the sentence stays
hardcoded splits one thought across two places and makes things worse, not better: the
panel is equally hardcoded either way. What these actually need is a recommendations model
holding the whole recommendation — title, body and figure generated together — which is a
table schema-v1 does not have. Filed as PIN-0010 rather than faked.
