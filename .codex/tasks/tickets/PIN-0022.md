# PIN-0022 — Dependency advisories

**Type:** Chore · **Phase:** 6 · **Status:** Review

Deferred from `.codex/specs/deploy.md` Q5 until after the first deploy, which has now
happened. 23 advisories: 1 low, 6 moderate, 16 high.

## What they actually are

All six affected **direct** packages are `devDependencies`:
`@cloudflare/vite-plugin`, `drizzle-kit`, `react-server-dom-webpack`, `vinext`, `vite`,
`wrangler`. The rest are transitive — undici, ws, esbuild, js-yaml, browserslist, postcss,
sharp, nanoid, brace-expansion, fast-uri, image-size.

"devDependency" is not the same as "not shipped", so that was checked rather than assumed.

### Two that needed a real answer

- **`image-size`, two high DoS advisories.** It **is** in the deployed bundle
  (`dist/server/index.js`) — vinext bundles it whether or not the image route exists, and
  PIN-0020 deleted that route. Nothing in Pinto parses an image at runtime: every image is a
  static file under `public/pinto/` served by the assets binding. So it ships but is
  unreachable.
- **`react-server-dom-webpack`, high, DoS in Server Functions.** Pinto has **no `"use server"`
  anywhere** — checked across `app/`, `db/` and `worker/`. Server functions are not used.

### Two that are Windows-only
Both `vite` advisories — the `launch-editor` NTLM disclosure and the `server.fs.deny` bypass —
are Windows path handling, and both are dev-server issues. เกรพ is on macOS and the dev server
is not exposed.

### One where npm's "fix" is a downgrade
`drizzle-kit` 0.31.10 → **0.18.1**, flagged breaking. That is thirteen minor versions
backwards to escape an advisory in `@esbuild-kit/esm-loader`. drizzle-kit runs only to
generate migration SQL, never at runtime. Downgrading it to satisfy a scanner would be
trading a real capability for a number.

## Approach
Take the non-breaking fixes, verify properly, and write down what is deliberately left —
with the reason, not just the number. A dependency bump that breaks the build is worse than
an advisory in a tool that never sees untrusted input.

## Acceptance criteria
- [x] Non-breaking fixes applied.
- [x] Whatever remains is listed below with why it is being left.
- [x] `npx tsc --noEmit`, `npm run build`, `npm run lint`, `npm test` pass.
- [x] The deployed site still works after the redeploy.

## What is left, and why

**4 moderate, all one chain:** `drizzle-kit` → `@esbuild-kit/esm-loader` → `esbuild`.

npm's only offered fix is `drizzle-kit@0.18.1` — **thirteen minor versions backwards**, and
flagged breaking. drizzle-kit runs in exactly one place, `npm run db:generate`, to turn
`db/schema.ts` into migration SQL. It never runs in the Worker, never at request time, and
never sees input that is not in this repository. Downgrading a working tool to satisfy a
scanner would trade a real capability for a smaller number.

**Left deliberately. Revisit when drizzle-kit publishes a forward fix.**

  unreachable.
- **`react-server-dom-webpack`, DoS in Server Functions.** Pinto has no `"use server"`
  anywhere, checked across `app/`, `db/` and `worker/`.

And the two `vite` advisories were both Windows path handling in the dev server. เกรพ is on
