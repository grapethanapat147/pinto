# PIN-0010 — Model the "Pinto แนะนำ" recommendation panels as data

**Type:** Feature · **Phase:** 3 · **Status:** Done

Carried over from PIN-0009, which left one acceptance criterion open rather than faking it.

## Goal
Three advisory panels still hold hardcoded amounts — the last `฿` literals in
`app/components/`:

| View | Amount | Where it sits |
| --- | --- | --- |
| Stock | ฿24,600 | at the end of the body sentence |
| Growth | ฿1,200 | **mid-title**: "โยกงบ ฿1,200 ไปที่ Ceramic Set" |
| Growth | ฿2,080 | figure box, as `+ ฿2,080 / วัน` |
| Customers | ฿46,700 | figure box |

PIN-0009 deliberately did not extract these: pulling the number out while the sentence
stays hardcoded splits one thought across two places and improves nothing.

## Design — templates, not display strings
Storing the finished sentence would repeat the mistake schema-v1 F3 identified: a number
frozen into text can never be recomputed. Instead each text field is a **template with an
`{amount}` placeholder** plus the amount as integer satang, interpolated on read.

So money stays an integer everywhere, and the sentence stays one unit — which is what it
will be when something eventually generates these.

### Templates rather than sentences
The obvious move was to store the finished sentence. That would have repeated the mistake
schema-v1 F3 identified — a number frozen into prose can never be recomputed. Instead each
text field is a template with an `{amount}` placeholder and the amount lives in its own
integer satang column, interpolated on read.

It matters most for Growth, where the amount is **mid-title**:
`"โยกงบ {amount} ไปที่ Ceramic Set"` + `120000`. Pulling the number out of that sentence
into a separate tile would have been the split PIN-0009 refused to make; a template keeps
the sentence whole *and* the money an integer.

The boxed figure carries its own prefix and suffix rather than baking them into text, so
`+ ฿2,080 / วัน` is `"+ "` · `208000` · `" / วัน"`.
